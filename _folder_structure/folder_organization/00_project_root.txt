MAIN CONFIGURATION RELATIONSHIPS

package.json
    cache:ids   -> public/scripts/generate-cache-ids.js
    build       -> cache IDs, then build Pages Functions into .wrangler/pages-build
    build:check -> build Pages Functions without cache-ID generation
    dev         -> cache IDs, then start Wrangler Pages development
    test        -> build:check

wrangler.jsonc
    pages_build_output_dir -> ./public
    KV bindings            -> AUTH_SESSIONS, RL_STATS_CACHE
    R2 bindings            -> OCR_TRAINING, OCR_STORAGE, OCR_PROGRESS
    queue producer         -> OCR_JOB_QUEUE on bpd-ocr-jobs
    service binding         -> OCR_GOOGLE_TRANSPORT / bpd-ocr-cloud-run-proxy
    custom domain           -> ocr-transport.bpd-gaming-network.com (secret gated)
    service URLs           -> OCR processor, OCR job callbacks, Supabase,
                              MMR API, and Rocket League presence monitor
    public identity/config -> OAuth and authorization identifiers used by runtime

ROOT-LEVEL RUNTIME BOUNDARIES

    public/ + functions/
        One Cloudflare Pages application. The browser assets and file-based
        functions share wrangler.jsonc bindings.

    workers/*
        Separate Worker deployments. Each child has its own wrangler.jsonc.
        OCR adds a Google auth/transport Worker bound to Pages; its custom
        domain is gated by a server-to-server shared secret.

    ocr_cloudData/
        Separate containerized Python service. The OCR transport Worker
        calls the configured OCR_API_URL rather than importing Python.

    Notes/
        Support/reference material, not a runtime import boundary.
